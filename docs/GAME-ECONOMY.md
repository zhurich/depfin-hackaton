# Игровая экономика: формулы и правила

Раздел 5, пункт 6 ТЗ. Все константы собраны в
[`web/src/domain/rules.ts`](../web/src/domain/rules.ts) — баланс игры меняется
без правки логики.

> Игровая валюта — **финики (Ф)**. Реальной стоимости не имеет, не продаётся и
> не обменивается.

---

## 1. Игровой период

Игровой период — одна **игровая неделя**. Цикл:

1. приходит доход;
2. ребёнок составляет план личного бюджета по трём направлениям;
3. покупает, выполняет задания, откладывает в копилку;
4. завершает неделю → сравнение плана с фактом, начисление очков роста,
   снижение показателей питомца, новый доход.

Продолжительность к реальному времени не привязана: неделя заканчивается тогда,
когда ребёнок нажимает «Завершить неделю». Поэтому демонстрационный сценарий из
пяти периодов проходится подряд.

---

## 2. Доходы

| Источник | Сумма | Когда |
| --- | --- | --- |
| Стартовый бюджет | **120 Ф** | Однократно, при создании питомца |
| Доход за неделю | **100 Ф** | В начале каждого следующего периода |
| Награда за задание | **16–30 Ф** | За выполнение задания (см. §6) |
| Бонус за вход | **10 Ф** | Не чаще 1 раза в календарный день, не более 3 раз за период |
| Баллы от взрослого | **20 Ф** | По решению взрослого, не более 40 Ф за период |

Каждое начисление попадает в журнал `ledger` с источником и суммой.
**Баланс не меняется без записи в журнале** — это видно ребёнку на экране
«Прогресс → Откуда финики».

Ограничение на баллы взрослого (40 Ф за период при доходе 100 Ф) поставлено
намеренно: бонусы не должны подменять планирование.

---

## 3. План личного бюджета

План — распределение доступной суммы по трём направлениям:

```
план.нужное + план.желанное + план.копилка  ≤  доступный баланс
остаток = доступный баланс − сумма плана
```

**Жёсткое правило:** сумма плана не может превысить бюджет. Ползунок и счётчик
каждого направления ограничены сверху величиной `бюджет − сумма остальных`, то
есть перерасход невозможен даже технически.

**Мягкие подсказки** (не блокируют подтверждение):

| Условие | Подсказка |
| --- | --- |
| `план.нужное < 45` | «На еду и уход обычно нужно около 45 фиников» |
| `план.копилка = 0` | «В копилку ничего не отложено» |
| `остаток > 0` | «Ещё не разложено N фиников» |

Подсказки именно мягкие, потому что по ТЗ отказ от необязательной покупки и
перенос её на следующий период ошибкой не считаются.

---

## 4. Сравнение плана с фактом

Допуск: **±10 Ф** (`PLAN_TOLERANCE_ABS`). Для расходов «уложился» значит
«потратил не больше плана», для накоплений — «отложил не меньше плана»:

```
нужное/желанное:  уложился  ⟺  факт − план ≤ 10
копилка:          уложился  ⟺  факт + 10 ≥ план
```

План считается выполненным, когда уложились **оба** направления расходов:

```
планВыполнен = уложился(нужное) И уложился(желанное)
```

## 5. Покупки

Каталог: 12 позиций — 5 обязательных и 7 необязательных
([`shop.ts`](../web/src/content/shop.ts)).

Покупка разрешена, когда выполнены оба условия:

```
цена ≤ баланс
куплено за период < лимит позиции
```

**Отрицательный баланс невозможен.** При нехватке средств вместо ошибки
показывается объяснение и список вариантов:

| Вариант | Когда предлагается |
| --- | --- |
| Выполнить задание | Есть невыполненные задания (указывается средняя награда) |
| Взять дешевле | В каталоге есть доступная позиция того же типа |
| Снять из копилки | В копилке активной цели что-то есть |
| Отложить до следующей недели | Всегда |

Последний вариант присутствует всегда и сформулирован как «Отказаться от
желанного — это не ошибка».

### Влияние покупок на питомца

| Позиция | Тип | Цена | Эффект |
| --- | --- | --- | --- |
| Каша | обязательная | 20 | сытость +30 |
| Обед с овощами | обязательная | 35 | сытость +45, радость +5 |
| Чистая вода | обязательная | 10 | сытость +10, уход +5 |
| Купание и уход | обязательная | 25 | уход +45 |
| Осмотр у доктора | обязательная | 40 | уход +25, сытость +10, радость +5 |
| Наклейки | необязательная | 20 | радость +15 |
| Мячик | необязательная | 25 | радость +20 |
| Книжка | необязательная | 30 | радость +18 |
| Цветок в горшке | необязательная | 35 | радость +20, уход +5 |
| Шапочка | необязательная | 45 | радость +28 |
| Кораблик | необязательная | 55 | радость +32 |
| Праздничный торт | необязательная | 60 | радость +35, сытость +10 |

Минимальный набор «каша + купание» = **45 Ф** — это и есть порог
`ESSENTIAL_NEED_COST`, на который ориентированы подсказки.

## 6. Накопления и цель

```
остаток до цели = max(0, стоимость − накоплено)
прогресс        = min(1, накоплено / стоимость)
```

### Срок достижения цели

ТЗ требует, чтобы срок считался по средней сумме регулярного пополнения:

```
среднее = (сумма всех пополнений) / (число периодов, в которых пополнение было)
срок в неделях = ⌈остаток до цели / среднее⌉
```

Среднее считается **только по периодам с пополнением**. Пропущенная неделя не
должна выглядеть так, будто ребёнок навсегда стал копить вдвое медленнее.

Если пополнений ещё не было, срок **не показывается вовсе** — вместо выдуманного
числа выводится «Пополни копилку хотя бы один раз — и мы посчитаем».

### Снятие из копилки

Требует отдельного подтверждения. До подтверждения показывается:

- новая сумма копилки: `накоплено − снимаемое`;
- изменение срока: `срок_после − срок_до` недель.

Снять больше, чем накоплено, нельзя.

## 7. Финансовые задания

9 заданий по 3 темам, 5 видов взаимодействия. Награда:

```
решение разумное   →  награда = базовая (+ бонус варианта для choice)
решение неточное   →  награда = max(1, ⌊базовая × 0,5⌉)
```

**Награда есть всегда.** Попытка не остаётся без результата — это прямое
следствие принципа «безопасная ошибка» (ТЗ п. 2.2). Объяснение выдаётся тоже
всегда, независимо от правильности.

Правила «разумности» по видам:

| Вид | Засчитывается, когда |
| --- | --- |
| `allocate` | Сумма не превышает выданную И соблюдены минимумы по направлениям |
| `basket` | Корзина в рамках бюджета И содержит все обязательные позиции |
| `order` | Порядок совпадает с правильным полностью |
| `number` | Отклонение ответа от верного не больше допуска |
| `choice` | Выбран вариант, помеченный как разумный |

Перерасход в `allocate` разбирается отдельной формулировкой со ссылкой на
правило «расходы не должны превышать доходы».

## 8. Состояние питомца

Три показателя, каждый от 0 до 100:

| Показатель | Растёт от | Снижение за период |
| --- | --- | --- |
| Сытость | еды | −35 |
| Уход | купания и осмотра | −30 |
| Радость | необязательных покупок и заданий | −15 |

Значения всегда ограничены диапазоном 0…100.

### Настроение

Производная величина, по ней рисуется мордочка:

```
критично = сытость < 45 ИЛИ уход < 45
среднее  = (сытость + уход + радость) / 3

грустит   ⟸ критично ИЛИ среднее < 45
спокоен   ⟸ среднее < 70
радуется  ⟸ иначе
```

Ребёнку всегда показывается **причина** настроения текстом, а не только смайлик:
«Финни проголодался. Купи ему еду».

> **Чего в игре нет.** Питомец не может заболеть, пострадать или погибнуть от
> решений ребёнка. Худшее состояние — «грустит», и оно всегда сопровождается
> понятным способом исправить ситуацию. Это требование ТЗ п. 2 и п. 3.5.

## 9. Развитие питомца

Очки роста начисляются при закрытии периода:

| За что | Очки | Условие |
| --- | --- | --- |
| Обязательные нужды закрыты | **+2** | сытость ≥ 45 И уход ≥ 45 |
| Факт совпал с планом | **+2** | уложился по нужному и желанному |
| Копилка пополнена | **+2** | факт.копилка > 0 И факт.копилка + 10 ≥ план.копилка |

Максимум за период — **6 очков**.

Условие для копилки требует, чтобы в неё действительно что-то положили: план
«отложить 0» не приносит очки за регулярность накоплений.

### Ключевое свойство: прогресс не обнуляется

```
очки_после = очки_до + начислено   (начислено ≥ 0)
```

Очки роста **никогда не убывают**. Неудачная неделя приносит 0 очков, но не
отнимает достигнутое — питомец не «откатывается» на предыдущую стадию. Это
проверяется тестом `period.test.ts` → «очки роста только накапливаются».

### Стадии

| Стадия | Порог | Что означает |
| --- | --- | --- |
| Малыш | 0 | Начало игры |
| Почемучка | 6 | Обязательные расходы не забываются |
| Знаток | 14 | Траты совпадают с планом |
| Мудрый Финни | 24 | Планирование и регулярные накопления вошли в привычку |

За 5 периодов максимум 30 очков, поэтому последняя стадия достижима в рамках
демонстрационного сценария. Это закреплено тестом, чтобы расширение контента не
сломало баланс.
