# Питомец Финни

Мобильное приложение: игровой сервис формирования базовых
финансовых навыков у детей 7–11 лет. Ребёнок заводит виртуального питомца,
получает игровую валюту, планирует её распределение на обязательные и
необязательные расходы, копит на цель и выполняет финансовые задания. Состояние
и развитие питомца зависят от принятых решений.

Прототип выполнен по техническому заданию Департамента финансов города Москвы
(хакатон «Лидеры цифровой трансформации», 2026).

> **Границы прототипа.** Реальных денег, банковских счетов, платежей, рекламы,
> внутриигровых покупок и сбора персональных данных в приложении нет. Игровая
> валюта («финики») не продаётся и не обменивается.

## Быстрый запуск

### Веб-слой в браузере (самый быстрый способ посмотреть)

```bash
cd web
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (по умолчанию `http://localhost:5173`).
Приложение полностью работоспособно в браузере: нативный мост не обязателен, а
прогресс сохраняется в `localStorage`.

Для проверки мобильной вёрстки включите в DevTools эмуляцию устройства шириной
360 px.

### Тесты

```bash
cd web
npm test
```

144 теста: правила экономики, контент и сквозной проход обязательного сценария
(Приложение А ТЗ) в DOM-окружении.

## Сборка APK

### Требования к окружению

| Инструмент | Версия | Проверено на |
| --- | --- | --- |
| JDK | 17 (Temurin) | 17.0.20.1+1 |
| Node.js | ≥ 20 | 24.21.0 |
| npm | ≥ 10 | 11.19.0 |
| Android SDK Platform | 35 | 35 |
| Android SDK Build-Tools | 35.0.0 | 35.0.0 |
| Gradle | через wrapper | 8.9 |
| Android Gradle Plugin | — | 8.6.1 |
| Kotlin | — | 1.9.24 |

### Шаг 1. Собрать веб-слой

```bash
cd web
npm ci
npm run build
```

Сборка складывается в `web/dist`, после чего скрипт `scripts/sync-native.mjs`
раскладывает её по оболочкам: в `android/app/src/main/assets/www` и в
`ios/FinniPet/www`. Этот шаг обязателен — собранные файлы не хранятся в
репозитории. Если его пропустить, Gradle остановится с понятным сообщением.

Собрать только веб, без раскладки: `npm run build:web`.
Разложить уже собранное: `npm run sync`.

### Шаг 2. Указать путь к Android SDK

Создайте `android/local.properties`:

```properties
sdk.dir=C\:\\путь\\к\\android-sdk
```

### Шаг 3. Собрать APK

Отладочная сборка:

```bash
cd android
./gradlew assembleDebug
```

Результат: `android/app/build/outputs/apk/debug/app-debug.apk`

Релизная сборка:

```bash
cd android
./gradlew assembleRelease
```

Результат: `android/app/build/outputs/apk/release/app-release.apk`

Дополнительно можно собрать AAB: `./gradlew bundleRelease`.

### Подпись релиза

Параметры подписи читаются из `android/keystore.properties`, которого нет в
репозитории (ТЗ п. 3.4 — пароли и закрытые ключи подписи в репозиторий не
попадают). Образец — `android/keystore.properties.example`.

Создать свой ключ:

```bash
cd android
mkdir -p keystore
keytool -genkeypair -v -keystore keystore/finni-release.jks \
        -alias finni -keyalg RSA -keysize 2048 -validity 10000
```

Затем скопируйте `keystore.properties.example` в `keystore.properties` и
впишите значения. Если файла нет, `assembleRelease` соберёт **неподписанный**
APK — сборка при этом остаётся воспроизводимой.

Проверить подпись:

```bash
$ANDROID_HOME/build-tools/35.0.0/apksigner verify --verbose \
    app/build/outputs/apk/release/app-release.apk
```

### Установка на устройство

```bash
adb install -r android/app/build/outputs/apk/release/app-release.apk
```

## Сборка для iOS

iOS в обязательный конкурсный минимум не входит (ТЗ п. 3.2). Для сборки нужен
macOS с Xcode. Порядок сборки, отличия от Android и список проверок после
сборки — в [`ios/README.md`](ios/README.md).

Коротко:

```bash
cd web && npm ci && npm run build
cd ../ios && xcodegen && open FinniPet.xcodeproj
```

## Демонстрационный режим и тестовый профиль

Демонстрационный режим включается в приложении:
**Главный экран → «Раздел для взрослого» → решить пример → «Демонстрационный
режим»**.

В этом режиме:

- все задания обязательного сценария доступны сразу, без привязки к реальному
  времени;
- бонус за вход не ждёт наступления следующего календарного дня;
- пять игровых периодов проходятся подряд.

Там же доступны:

- **«Сбросить профиль к началу»** — тестовый профиль возвращается к исходному
  состоянию, обязательный сценарий проходится заново, настройки сохраняются;
- **«Удалить все данные»** — полное удаление локального профиля с устройства.

Пошаговый сценарий демонстрации: [`docs/TEST-CASES.md`](docs/TEST-CASES.md).

## Как добавить новое задание

Задания — это данные, а не код. Чтобы добавить задание, допишите объект в
массив `QUESTS` в [`web/src/content/quests.ts`](web/src/content/quests.ts) и
пересоберите веб-слой. Логика приложения не меняется (ТЗ п. 2.5.14).

Подробнее — [`docs/CONTENT-MAP.md`](docs/CONTENT-MAP.md), раздел «Как расширять
контент».
